# Upper Kurast crash investigation

User report: Act III, Upper Kurast, outside combat, after having also visited
the following area. Process 22344, current build 0.12.16. The captured report
was generated at 2026-11-12 00:10:37 UTC (01:10:37 CET); the filename retains
an earlier session timestamp and should not be treated as the crash time.

The access violation is at D2RLoader.exe+0x95f755, reading address
0x7c7482934. Read-only inspection of saved native code shows a failed entity
handle/vector access during recursive native graphics/resource destruction,
with callers +0x95f907, +0x95e12e and +0x67ead1. No direct Workshop combat or
MapSense frame is established in the captured stack slots. This is a different
signature from the earlier Hell Ancient spawn/equipment crash (+0x4951ea).

MapSense had recently built the Act III native atlas and processed levels
82 then 81. Its final entries record character-panel clipping transitions
and a return to the world HUD. This timing makes a map/UI transition worth
isolating, but does not establish MapSense as the cause. Neither the native
map reveal feature nor unrelated combat mechanics were disabled speculatively.
The character-display string assertion found earlier in the loader log is
also recorded, but is not proven to have caused this later graphics failure.

The exact report and pre-restart plugin logs are preserved locally under
`build/diagnostics/2026-11-12-upper-kurast/`; the original WER dump remains in
the user's CrashDumps directory. A repeat with knowledge of map visibility
and active Ancients is needed before making a native crash fix. Startup/data
checks cannot validate absence of this intermittent crash.


User follow-up: the Tab automap was open and no Ancients were active at the
time of the crash. This lowers the priority of Ancient combat/despawn as a
reproduction trigger and makes map-open room/scene transitions the next test.
The responsible native owner is still unproven; MapSense remains enabled.


Further user confirmation: no Ancients had been summoned in that game
session at all. Do not attribute this crash to active Ancient AI or timed
removal without independent evidence. A fresh-process map-open comparison
remains the appropriate isolation step; no speculative native patch was made.
